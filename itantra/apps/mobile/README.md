# iTantra mobile (React Native / Expo)

The field app. It renders the same `ITantra` contract as the web app, but through a native Expo
module instead of a Capacitor WebView. The Kotlin engine and the wire protocol are shared with
the rest of the monorepo; only the UI shell differs.

## Layout

- `app/` — expo-router screens. `index.tsx` is the current toolchain spike.
- `modules/itantra-native/` — local Expo module. Its `android/build.gradle` compiles the shared
  sources from `../../android/core-protocol/src/main/kotlin`, so the app and the JVM tests use the
  exact same codec.
- `android/` — generated by `expo prebuild` (do not hand-edit; use config plugins).

## Prerequisites

- JDK 17 and the Android SDK (`ANDROID_HOME`), plus the NDK that React Native asks for.
- This directory is **not** part of the pnpm workspace, to avoid Metro/pnpm symlink issues. It has
  its own `.npmrc` (`node-linker=hoisted`) and lockfile.

## Commands

```bash
# from apps/mobile
pnpm install --ignore-workspace
npx expo prebuild --platform android --no-install   # regenerate android/
npx tsc --noEmit

# build a debug APK (first run downloads Gradle/NDK and takes a while)
cd android
JAVA_HOME=<jdk17> ANDROID_HOME=$HOME/android-sdk ./gradlew :app:assembleDebug
# -> android/app/build/outputs/apk/debug/app-debug.apk

# offline release APK: no INTERNET permission, arm64 only
ITANTRA_OFFLINE=1 npx expo prebuild --clean --platform android --no-install
cd android
JAVA_HOME=<jdk17> ANDROID_HOME=$HOME/android-sdk ./gradlew :app:assembleRelease \
  -PreactNativeArchitectures=arm64-v8a -x lintVitalRelease
# -> android/app/build/outputs/apk/release/app-release.apk
```

`ITANTRA_OFFLINE=1` makes `plugins/withOfflineManifest.js` add
`<uses-permission android:name="android.permission.INTERNET" tools:node="remove"/>`, so the merged
manifest has no INTERNET. Omit it for normal development, where Metro needs the network.

## Release signing

`plugins/withReleaseSigning.js` signs release builds with a project keystore when
`credentials/key.properties` exists (otherwise it falls back to the debug key). Create it locally;
both files are git-ignored and must never be committed:

```bash
mkdir -p credentials
keytool -genkeypair -v -keystore credentials/itantra-release.keystore -alias itantra \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <pass> -keypass <pass> -dname "CN=iTantra, O=iTantra, C=IN"
printf 'storePassword=<pass>\nkeyAlias=itantra\nkeyPassword=<pass>\n' > credentials/key.properties
```

Verify the built APK:

```bash
$ANDROID_HOME/build-tools/36.0.0/apksigner verify --print-certs \
  android/app/build/outputs/apk/release/app-release.apk | grep "certificate DN"
# -> Signer #1 certificate DN: CN=iTantra, ...
```

If the Gradle wrapper cannot download its distribution in time, raise `networkTimeout` in
`android/gradle/wrapper/gradle-wrapper.properties` or build with a locally installed Gradle of
the same version.

## Screens

- Tabs: Talk, Thread, Alerts, Packs, More.
- Stack: Setup, Peers (with the 6-digit SAS sheet), and a native spike screen.
- State lives in `lib/app.tsx`; the contract in `lib/bridge`; field tokens in `lib/theme.ts`.
- Until the Kotlin engine service is wired, `lib/bridge` uses a mobile `MockBridge` with scripted
  behaviour (the same one the web uses). `createBridge()` switches to `NativeBridge` as soon as the
  native module exposes `getState`.

## What the native module proves

`modules/itantra-native` compiles the shared pure-Kotlin modules (`core-protocol`,
`core-transport`, `core-speech`, `engine-service`) directly from `apps/android`, so the app and the
JVM tests run identical code. It exposes:

- `scriptRoundTrip(lang, text)` — the script-aware codec
- `frameInfo(lang, text)` — a real authenticated frame (C1), with header/payload/tag/frame sizes
- `vadDemo()` — `EnergyVad` on a synthetic buffer (focus area 1)
- `metricsCsv()` — the latency timeline (focus area 5)
- `outboxDemo()` — alert-before-routine ordering and TTL expiry (focus area 3)

The `/dev` screen calls all of them. The release APK bundles the JS
(`assets/index.android.bundle`) and links that Kotlin code (verified in the dex). The next step is
to grow `modules/itantra-native` into the full `ITantra` contract over the engine service.
