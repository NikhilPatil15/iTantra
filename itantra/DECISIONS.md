## 2026-09-28 — Protocol deviations from the research doc

| Decision | Reason |
| --- | --- |
| Replace "minutes since session epoch" with `ageSeconds` | Works without synchronised clocks; plan Section 7.1. |

| Next.js `app` uses `output: 'export'` and no dynamic segments | Required by Capacitor static WebView; plan Section 16.10. |

### Send/receive orchestrator core (2026-09-29)

`ProtocolSession` (engine-service) wires the script codec, AEAD framing, de-duplication and
reordering into one testable object with `buildText`, `buildAck`, `receive` and `expire`. Evidence:
`ProtocolSessionTest` 8 tests pass — text round trip, duplicate rejection, stale rejection, tamper
detection, out-of-order hold-then-in-order delivery, forced expiry and ALERT_TEXT priority. It is
also exposed to the app as `sessionDemo`. Kotlin JVM total is now 43 tests.

### End-to-end in-process engine (2026-09-29)

`InProcessEngine` runs the Gate G5 flow with a scripted ASR fake: recognise → read-back with
per-word confidence → accept (or edit) → real codec/AEAD framing → de-dupe/reorder → ACK → metrics
row. `InProcessEngineTest` 5 tests pass, and the same flow is exposed to the app as `engineDemo` on
the `/dev` screen. Kotlin JVM total is now 48 tests. The release APK (40.4 MB, 0 INTERNET) now
contains `InProcessEngine`, `ScriptedAsrEngine` and `ProtocolSession`.

### Field screens on the native engine (2026-09-29)

`EngineBridge` (apps/mobile/lib/bridge/native.ts) extends the mock and overrides the field-flow
methods to call `ITantraNative` (`startEngine`, `getEngineState`, `beginTalk`, `acceptReadback`,

### Real transports (2026-09-29)

`BluetoothTransport` (Bluetooth Classic RFCOMM on a fixed app UUID, bonded-device discovery,
accept loop, `[len:uint16][frame]` stream framing) and `WifiDirectTransport` (`WifiP2pManager`
discovery + group formation, TCP on port 8988 inside the P2P group, group owner runs the server)
are implemented. They use Android APIs, so they live in `core-transport/src/androidMain/kotlin`
and are added to the Expo module's source sets; the pure-JVM `core-transport` module is unchanged
and still tests `LoopbackTransport`/`EmulatedLink`.

Evidence: `:app:assembleRelease` succeeds (40.4 MB, 0 INTERNET); the dex contains
`BluetoothTransport` and `WifiDirectTransport`. **Caveat:** neither has been run on real phones;
link behaviour and OEM Wi-Fi Direct quirks remain unverified and must not be claimed.

### Transport-agnostic engine (2026-09-29)

`LinkedEngine` moves whole frames over the `Link` interface and uses `ProtocolSession` for the
codec, AEAD, de-duplication and reordering. It is tested over `LoopbackTransport`
(`LinkedEngineTest` 3 pass) and accepts `BluetoothTransport` / `WifiDirectTransport` on device
without changing the field flow. Kotlin JVM total is now 54 tests. Integration tests use real-time
`runBlocking` rather than virtual time, because flows over channels do not advance correctly under
the test scheduler; the receive path is also exposed as a direct `receiveFrame` for deterministic
tests.

### Deviations / cautions

- The Gradle wrapper's default 10 s `networkTimeout` could not fetch Gradle 9.3.1; it was raised
  to 120 s and the build was run with a locally downloaded Gradle 9.3.1.
- Both the debug (254 MB) and release (97.6 MB) APKs declare `android.permission.INTERNET`,
  inherited from the React Native/Expo manifests and `expo-dev-client`. The "no internet" claim
  therefore cannot be made from either build yet. Removing it needs a config plugin that deletes
  the permission from the merged manifest plus a socket audit (OPEN_QUESTIONS.md Q9). No app code
  opens a socket.
- The release APK still bundles `expo-dev-client`; remove it before a production build.
- ABIs are not split, so the release APK carries all four. `-PreactNativeArchitectures=arm64-v8a`
  roughly halves build time and APK size for a real device build.
- `expo-system-ui` is not installed, so `userInterfaceStyle: automatic` is inactive for now.
